# 企业部署

锁定环境下的推荐配置。建议以 [`config/enterprise.toml`](../../config/enterprise.toml) 为起点。

## 配置（`config/corex.toml` 或覆盖文件）

```toml
[runtime]
strict_permissions = true
filesystem_roots = ["C:/ProgramData/corex/data"]

[plugins]
disabled_actions = [
  "shell.run",
  "exec.run",
  "ui.window.list",
  "ui.window.desktop",
  "ui.window.focus",
  "ui.window.find",
  "ui.window.wait",
  "ui.element.list",
  "ui.element.find",
  "ui.element.point",
  "ui.element.pick",
  "ui.element.click",
  "ui.element.wait",
  "ui.element.exists",
  "ui.wait",
  "ui.click",
  "ui.type",
  "ui.key",
  "capture.ocr",
  "capture.screenshot",
  "capture.monitors",
  "keyring.get",
  "keyring.set",
  "scan.os",
]

[logging]
json = true
```

`strict_permissions` 会拒绝**未声明任何权限标志**的指令（视为 unrestricted）。  
同时拒绝 `corex ui` 探测命令，以及 daemon 对需权限 Action 的 `Invoke`（含全部 `ui.*`）。  
`corex validate --strict` 还会检查：声明的权限是否覆盖每一个步骤的 Action 类别。

设置 `filesystem_roots` 后，`file.*` / `copy.*` / `codec.*` 等路径 I/O，以及 `exec.run` 的 **script**、`shell.run`/`exec.run` 的 **cwd**，必须解析到这些根目录之下。`shell.run` 的 **command** 不做路径沙箱（走 PATH 查找）。

仅在确有需要时，从 `disabled_actions` 中移除对应 ID（和/或清空 `plugins.disabled`），并在指令中声明匹配的 `permissions`。

部署前校验：

```bash
corex validate --strict path/to/directive.yaml
```

## 指令权限

始终声明最小权限集：

```yaml
permissions:
  network: true    # http.send
  filesystem: true # file.write, file.read, codec.*, copy.*, …
  shell: true      # shell.run / exec.run
  clipboard: true  # clipboard.get/set
  ui: true         # ui.*
  capture: true    # capture.screenshot / capture.ocr / capture.monitors
  secret: true     # keyring.*
```

## IPC

- 设置 `COREX_TOKEN` 或 `[daemon].token`；Unix 上将 `<data-dir>/token` 权限设为 `0600`。
- 不要把 daemon 的 socket/pipe 暴露给不可信用户。

## 日志与审计

- `[logging].json = true` 便于 SIEM 采集。
- 步骤审计写入 `<data-dir>/audit.jsonl`（`action_id`、`duration_ms`、`ok`）。
- 指令级 `history.jsonl` 仅保留短错误类别（已脱敏，非完整异常文本）。
- 日志不得包含 HTTP body 或 OCR 全文（引擎侧已脱敏）。

## 最小企业构建

默认 CLI/daemon 启用 `full`（全部 `act-*` + WASM）。为缩小攻击面，可只编译需要的 gate：

```bash
cargo build -p corex -p corex-daemon --release --no-default-features \
  --features act-file,act-template,act-http
```

在 Windows 上，`act-ui` / `act-capture` / `act-shell` / `act-exec` 会拉取对应的 `windows` API 包（`win32-base`、`winrt-ocr`、`win32-process`）。见 [actions.md](../reference/内置Action.md)。

建议将最小构建与运行时 `config/enterprise.toml`（`disabled_actions` + `strict_permissions`）一起使用。

## CLI 信任边界

`corex run` **在进程内**执行指令，不经过 daemon IPC。任何能运行该二进制并读取非严格配置的本地用户，都可能调用需权限的 Action。生产部署应：

1. 对不可信客户端优先使用 `corex-daemon` + IPC token。
2. 限制 `corex` / `corex-daemon` 二进制以及 `config/enterprise.toml` / 数据目录的文件系统 ACL。
3. 若运维人员同时拥有 `corex run` 的 shell 权限，不要假设「仅 daemon 安全」。
