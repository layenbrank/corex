# 故障排查

> 按**现象**查表。每条都给出「怎么确认」与「怎么修」，而不是只给结论。
> 想先要一份体检报告：`corex doctor`（数据目录、配置、守护进程、动作与指令）。

---

## 0. 先做这三件事

```powershell
corex doctor                 # 数据目录 / 配置 / daemon / 动作 / 指令 自检
corex validate               # 不带路径 = 检查配置，报告生效的是哪份文件
corex history --failed -n 10 # 最近 10 次失败（含脱敏后的错误文本）
```

要更细的日志：`corex -v run <名称>`（debug）/ `-vv`（trace），或
`COREX_LOG=corex_engine=debug`。**日志写 stderr、结果写 stdout**，所以加了 `-v` 也不会污染
`corex run x | jq`。

退出码本身也是线索：`2` = 写法/配置问题、`3` = 被策略拒绝、`1` = 跑失败。见
[退出码与错误码](../reference/退出码与错误码.md)。

---

## 1. 指令找不到 / 跑不起来

| 现象                                  | 原因                                                                      | 处理                                                                                                                                                |
| ------------------------------------- | ------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `指令未找到`                          | 名字带了 `.yaml`，或不在搜索路径里                                        | 参数写**不含扩展名**的名称；搜索顺序为 当前目录 → `<数据目录>/directives/` → 仓库 `examples/directives/`。`corex schedule` 看全部，`--dir` 指定目录 |
| `动作未注册`                          | 该 Action 由 **WASM 插件**提供，而 `corex run` **刻意从不加载插件**       | 走 daemon：`corex run <名称> --remote`（或 IPC 调用）。见 [IPC 接入指南](../integration/IPC接入指南.md)                                             |
| 非终端（CI / 脚本）里省略指令名就报错 | 省略名称 = 交互挑选，非终端下是用法错误（退出码 2），**不会静默挑一个跑** | 显式给名称，或 `-y` 让缺参直接报错                                                                                                                  |
| `permission denied`                   | 指令声明了 `permissions` 但没覆盖某个步骤所需类别                         | 见 [第 4 节](#4-权限与策略)。退出码是 **3**，不是 1                                                                                                 |
| 可选输入没传，步骤里是 `null`         | 没写 `default`                                                            | 见 [指令与输入配置](../guide/指令与输入配置.md#3-默认值default)                                                                                     |

## 2. 配置

| 现象                     | 原因                                                                                  | 处理                                                                                                                                  |
| ------------------------ | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 命令直接失败，退出码 2   | 配置文件**存在但解析失败** → 不回落到默认值（刻意的：否则拼错的安全开关会被无声关掉） | `corex validate` 指出问题与生效的配置文件                                                                                             |
| 「未知的键 / section」   | **未知的 section 或键会被拒绝**                                                       | 多半是拼写（`strict_permissons`）；对照 [运行时配置](../guide/运行时配置.md) 全量表                                                   |
| 改了配置但没生效         | 没找到你改的那份                                                                      | 优先级：`--config` → `<数据目录>/config/corex.toml` → `<数据目录>/config.toml` → 当前目录 `config/corex.toml`；**找到即用，不做合并** |
| daemon 与 CLI 行为不一致 | 两边拿的配置/数据目录不同                                                             | 两边都设同一个 `COREX_DATA_DIR`，或用 `--config` 明示                                                                                 |

## 3. Daemon 与 IPC

| 现象                                               | 原因                                                                                       | 处理                                                                                     |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| Windows 上 daemon 启动失败，报错指向 `socket_path` | 默认端点**恒为 `\\.\pipe\corex`**，不随数据目录变；两个宿主抢同一个管道名                  | 给**每个宿主**一个 `socket_path`（如 `\\.\pipe\my-app-corex`）                           |
| 配置里写了 `corex.sock`，Windows 启动就被拒        | Windows 端点**只能是命名管道**；底层 `CreateNamedPipe` 的 os error 123 说不清原因          | 省略该项用平台默认，或写 `\\.\pipe\...`（TOML 单字面量 `'\\.\pipe\corex'`）              |
| `corex daemon status` 说“已停止”，但进程明明在     | token 来源三处不一致（v10 之前 CLI 只看「环境变量 + 文件」）                               | v10 起统一为 `corex_ipc::find_token`；先确认双方 `COREX_DATA_DIR` / `--config` 一致      |
| 401 `unauthorized`                                 | token 不对。**记录里没有 `token_file` 时不要去读 `<数据目录>/token`**——那属于上一个 daemon | 顺序：`COREX_TOKEN` → 配置 `[daemon].token` → 记录里的 `token_file` → `<数据目录>/token` |
| 「有 `endpoint.json`，但连不上」                   | 记录可能是**残留**（daemon 被强杀时来不及删）；`pid` 不做存活性判断                        | **有记录 ≠ 在跑**：发一条 `ping` 才算数                                                  |
| 宿主探活 `ping` 超时，看起来像失联                 | v10 之前同一条连接上是「跑完一条才读下一条」                                               | v10 已改为每请求一个任务；**跨请求顺序不保证，按 `id` 归位**才是正确读法                 |

端点发现与 token 的完整规则见 [IPC 协议](../reference/IPC协议.md) 与
[数据目录与状态文件](../reference/数据目录与状态文件.md)。

## 4. 权限与策略

| 现象                          | 原因                                                                  | 处理                                                                               |
| ----------------------------- | --------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 退出码 3，`denied: true`      | 权限/策略拒绝                                                         | `permissions` 声明覆盖该 Action 类别；`strict_permissions = true` 要求**必须声明** |
| `on_error: continue` 没吞掉它 | **权限拒绝始终中止**流水线（否则门禁可用 `continue` 绕过）            | 这是设计；修正权限声明，或从 `disabled_actions` 里移出                             |
| 动作报「已禁用」/ `disabled`  | 命中 `[plugins].disabled` 或 `disabled_actions`                       | 检查配置；企业模板见 [`config/enterprise.toml`](../../config/enterprise.toml)      |
| 文件类动作报路径不允许        | `[runtime].filesystem_roots` 限制（含 `exec.run` 的 script 与 `cwd`） | `corex validate <path> --strict` 会遍历每步核对权限                                |

## 5. Windows 输出与中文乱码

| 现象                                       | 原因                                                                           | 处理                                                                                                   |
| ------------------------------------------ | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| 直连控制台的中文正常，`\| Out-File` 后乱码 | 解码由 **PowerShell** 决定，不是 corex                                         | 在读方设一行：`[Console]::OutputEncoding = [Text.Encoding]::UTF8`                                      |
| `shell.run` / `exec.run` 的中文乱码        | 走的是**管道**，不是控制台代码页；中文 Windows 上 `cmd` 等按 OEM(CP936/GBK) 写 | corex 先按 UTF-8 解、失败再回退 OEM/GBK，并把实时回显转成 UTF-8；这与「只 `chcp 65001`」不是同一层问题 |
| 符号显示成方块                             | 终端/字体跟不上 `✓` / `⠋`                                                      | `COREX_ASCII=1` 换成纯 ASCII                                                                           |
| 需要纯文本输出                             | 颜色转义干扰                                                                   | `NO_COLOR=1` / `CLICOLOR=0`（重定向到文件时本来就会自动关）                                            |
| 想确认当前控制台编码                       | —                                                                              | `corex doctor` 会报「控制台编码」，`65001 (UTF-8)` 是正常                                              |

## 6. watch / cron

| 现象                             | 原因/处理                                                                                                              |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `send` / `stop` 报「找不到路径」 | 用**指令名**（`ps` 的 NAME 列），**不要用 pid**；`<id>` 目录名就是指令名                                               |
| 想看日志却启动了一个新实例       | 用 `attach` 看日志，`run` 是**启动**。`corex watch attach <name>`：Ctrl+C 只是 detach，**不停**守护                    |
| 想真的停掉                       | `corex watch stop <name>`（优雅）；`--force` 立即终止进行中的构建                                                      |
| job 显示存在但实际早没了         | `meta.json` 的存活判定要求 pid 在 + exe 路径匹配 + 启动时间在容差内；缺字段的旧 meta 视为失效，可由 `prune_stale` 清理 |

## 7. 网络

| 现象                                      | 原因                                                                                                  | 处理                                                                                        |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `http.send` 访问回环/内网地址返回 **502** | 机器上装了本地加速/代理软件（系统代理指向 `127.0.0.1:xxxx`），或终端里有 `HTTP_PROXY` / `HTTPS_PROXY` | 清掉代理变量，或把该地址加进 `NO_PROXY`，再重试；`curl` 直连成功而程序 502 基本可断定是代理 |
| 出站请求超时                              | 直连被拦                                                                                              | 设 `HTTPS_PROXY`（`corex update` 另见 `[update].use_system_proxy`）                         |
