# 威胁模型（corex v13 内置）

## 信任边界

| 组件 | 信任级别 | 说明 |
|------|----------|------|
| Directive（库里的、导入的） | 半可信 | 可声明步骤与权限；进库前过「动作已注册 / 权限够」两道门 |
| 指令库 `corex.db` | **可信** | 与配置同级的本地状态：谁能写它，谁就能定义要跑什么 |
| 直接给的 YAML 路径（`run --file` / `path` / `import`） | 半可信 | 调用方明确指的文件，daemon 照读 |
| corex-daemon | 可信 | 持有 IPC token，执行 Action |
| 内置 Action | 可信代码 | 编译期 feature 门控 |
| 外部 HTTP 目标 | 不可信 | `http.send` |
| 本地文件系统 | 敏感 | `file.write` 补丁模式等 |

## 高风险 Action

| Action | 风险 | 缓解 |
|--------|------|------|
| `shell.run` / `exec.run` | 任意进程 / 脚本 | `permissions.shell`；按 Action 的 `disabled_actions`；审计建议显式 `host`；`filesystem_roots` 约束 `exec.run` 的 **script** 与两者的 **cwd**（`shell.run` 的 **command** 不做路径沙箱——走 PATH） |
| `ui.*` | 输入注入、应用控制 | `permissions.ui`；企业预设默认关闭 |
| `capture.screenshot` / `capture.monitors` | 屏幕 PII/机密；显示器布局 | `permissions.capture`；企业预设禁用 |
| `capture.ocr` / `capture.find` / `capture.crop` | 读取任意图片文件 | `permissions.filesystem`，且路径受 `filesystem_roots` 约束；历史不写 OCR 全文 |
| `keyring.*` / `scan.os` | 密钥 / 主机清单 | `permissions.secret`（keyring）；企业 `disabled_actions` |
| `file.write`（`regex` 模式） | ReDoS | 模式长度与输出字节上限 |
| `clipboard.set`（`image`） | 读磁盘图片并经剪贴板外泄 | `permissions.clipboard` + `permissions.filesystem`；路径受 `filesystem_roots` 约束 |
| `corex ui` 探测 CLI | 枚举窗口/控件；stdout 可能含 PII | 与 daemon 相同的 `plugins.disabled` / `disabled_actions` / `strict_permissions`；审计为 `ui.probe`；可用 `--redact` |
| `corex update` 自更新 | 供应链：远端可替换正在运行的可执行文件；提权：写入高权限目录 | 三级 SHA-256 校验（GitHub asset digest + `SHA256SUMS.txt` + `.sha256` 旁车）全部一致才替换；替换前跑 `--version` 自检；**从不自行提权**；只替换 `corex.exe`，不动 daemon 与 DLL；`[update] enabled = false` 可完全关闭 |

## 指令的读写面（v13）

| 面 | 谁能写 | 说明 |
|----|--------|------|
| 库（`corex.db`） | 任何能写数据目录的进程 | 与 `token` / `audit.jsonl` 同级信任：**能写库 = 能定义要跑的 Action**。多用户机器上要限制数据目录的写权限 |
| IPC `save_directive` / `delete_directive` / `import_directives` | 持有 token 的调用方 | token 即权限；`import_directives.path` 是调用方给的**信任路径**，判定只作用于「能不能入库」 |
| `import_directives.path` / `run_directive.path` | 同上 | 从 v13 起**不再 confine 到某个「指令根」**：daemon 会读调用方指到的文件。要挡住越权读，用文件系统权限或 `[runtime].filesystem_roots`，别指望 daemon 猜哪个目录算「允许」 |
| `corex directive edit` 的临时文件 | 本机同一用户 | 写在 `<数据目录>/edit/<名字>.yaml`，编辑器退出后删除；内容有错时**故意留下**（否则用户刚写的改动会丢） |

指令名仍是**裸名**（无 `..` / `/` / `\` / 绝对路径）：它会影响临时文件名与审计字段，
所以这条规则在库时代照旧执行——由 `corex_store::validate_name` 统一判定。

## 已移除 / 已迁移

- **`capture.clipboard`** 已移除 — 改用 `clipboard.set`，`format: image` 或 `text`。
- **`ui.find` / `ui.wait`（窗口等待语义）** — 窗口等待改用 `ui.window.find` / `ui.window.wait`（固定休眠仍可用 `ui.wait`）。
- **v13**：指令与执行日志从「`directives/` 目录 + `history.jsonl`」迁进 `corex.db`；
  两个旧位置只在首次打开库时被读一次，导入**不会**删除原文件。

## 数据流

```
Directive（库 / 直接给的路径） → Pipeline → ActionStore → builtin / WASM
                ↓
         corex.db 的 runs 表（指令级）
         audit.jsonl（步骤级，已脱敏）
```

## 脱敏策略（已实现）

| 数据 | 是否记录 |
|------|----------|
| `action_id`、`step_id`、`duration_ms`、`ok` | 是（`audit.jsonl`） |
| `denied`（权限拒绝）、`error_kind` | 是（失败时；`denied: true` 表示权限拒绝） |
| `ui_phase`、`error_code`、`selector_hint` | 是（适用时；`selector_hint` 已脱敏） |
| 指令历史 `error` | 短类别 + 截断 / 路径脱敏文本（`corex.db` 的 `runs`，前缀常为 `kind:`） |
| HTTP body、OCR 全文、剪贴板载荷 | **否** |
| 敏感 Action 参数 | **不记录**（无参数值、无密钥转储） |

## 合规提示

- UI 自动化示例（如微信）为**实验性**；见 [compliance.md](合规说明.md)。
- 企业部署请启用 `strict_permissions` + `filesystem_roots`，并限制数据目录的写权限
  （库与 `token` 同级可信）。
- 本地 `corex run` 绕过 daemon IPC；见 [enterprise-deploy.md](企业部署.md#cli-信任边界)。
