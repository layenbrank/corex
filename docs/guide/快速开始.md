# 快速开始

本文帮助你在 **5～10 分钟内**完成安装、首次运行与基本命令了解。

---

## 前置条件

| 项目 | 要求 |
|------|------|
| 操作系统 | Windows / Linux / macOS（部分 Action 仅 Windows，如 `ui.*`、`capture.*`） |
| Rust | 1.85+（edition 2024） |
| 网络 | 运行 HTTP 类示例时需要 |

---

## 1. 构建

```powershell
git clone <repo-url>
cd corex
cargo build -p corex -p corex-daemon
```

Release 构建：

```powershell
cargo build -p corex -p corex-daemon --release
```

Windows 也可从 GitHub Release 下载 `corex-{tag}-windows-x64.zip`（含 `corex.exe`、`corex-daemon.exe`）。

### 贡献者：本地门禁（可选）

提交前建议安装 pre-commit 与相关 CLI（配置已在仓库根目录）：

```powershell
cargo install cargo-deny typos-cli git-cliff --locked
uv tool install pre-commit
pre-commit install
pre-commit run --all-files
```

- `cargo fmt -- --check`：严格格式门禁
- `cargo deny check` / `typos`：依赖策略与拼写
- `git-cliff -l`：预览 conventional changelog

发版（bump 版本、生成 `CHANGELOG.md`、打 tag）见 [发布与 Changelog](../ops/发布与Changelog.md)。
完整门禁说明见 [架构 — 构建与开发工具链](../reference/架构.md#构建与开发工具链)。

## 2. 运行第一个指令

```powershell
# 方式 A：按名称（在 examples/directives/ 或数据目录中查找）
corex run hello

# 方式 B：指定 YAML 路径
corex run examples/directives/hello.yaml

# 传入输入参数
corex run hello -i who=Corex
```

成功时终端输出 JSON，并在临时目录生成问候文件（默认 `%TEMP%/corex-hello.txt`）。

---

## 3. 查看可用指令与动作

```powershell
corex schedule
corex actions
```

| 命令 | 说明 |
|------|------|
| `corex run <名称\|路径>` | 执行指令；`-i KEY=VALUE` 传参 |
| `corex schedule` | 列出可用指令名 |
| `corex watch run\|attach\|ps …` | 文件监听守护：`run` 后台启动、`attach` 看日志（Ctrl+C 不停止） |
| `corex cron run\|attach\|ps …` | 定时调度守护（命令与 watch 对称） |
| `corex actions` | 列出已注册 Action ID |
| `corex validate <path>` | 校验 YAML；`--strict` 检查权限覆盖 |
| `corex create <name>` | 创建指令脚手架 |
| `corex repl` | 交互式 REPL |
| `corex daemon run` | 前台启动 Daemon（IPC 服务） |
| `corex daemon status` | 查看 Daemon 是否在运行 |
| `corex ui ...` | Windows UI 探测工具（见 [UI 自动化](../topics/UI自动化.md)） |

全局选项：

- `-v` / `-vv`：提高日志级别
- `--dir <路径>`：覆盖指令搜索目录

## 4. 指令文件放在哪？

解析顺序（`corex run <name>`）：

1. 当前路径下的 `<name>.yaml`
2. **数据目录** `directives/<name>.yaml`
3. 仓库 `examples/directives/<name>.yaml`

| 优先级 | 数据目录 |
|--------|----------|
| 1（优先） | `corex.exe` / `corex` **所在目录**（可写时；便携布局） |
| 2 | Windows `%LOCALAPPDATA%\corex\`；Linux `~/.local/share/corex/`；macOS `~/Library/Application Support/corex/` |
| 3 | 当前目录 `.corex` |

自定义指令可复制到 `<数据目录>/directives/`，或通过 `--dir` 指定目录。

## 6. 常见问题

### `指令未找到`

- 确认文件名与 `corex run` 参数一致（不含 `.yaml`）
- 或在仓库根目录执行，以便找到 `examples/directives/`

### `permission denied`

指令声明了 `permissions` 但未包含当前 Action 所需类别。见 [指令与输入配置 — 权限](./指令与输入配置.md#权限)。

### HTTP 示例超时

检查网络与 URL；可加大 `timeout_ms` 或使用 `-v` 查看日志。

### watch/cron：send 报错「找不到路径」

操作请使用 **指令名**（`ps` 的 NAME 列），不要用 pid。例如：`corex watch send build-client status`。

### watch/cron：`run` 和 `attach` 有什么区别？

| 命令 | 作用 |
|------|------|
| `corex watch run <name>` | **启动**后台文件监听守护（默认 detach） |
| `corex watch run <name> --foreground` | **前台**启动（开发用，`Ctrl+C` 会停止守护） |
| `corex watch attach <name>` | **查看**已在运行的守护日志（不启动新实例） |

`corex cron run` / `attach` 同理。查看日志用 `attach`，不要用 `run`。

### watch attach 退出后任务还在吗？

`corex watch attach` 按 `Ctrl+C` 仅退出查看（detach），**不会**停止后台守护；用 `corex watch stop <name>` 优雅停止，或 `corex watch stop <name> --force` 立即终止进行中的构建。

### Windows 上 `/tmp/...` 路径无效

使用 `-i out="{{env.TEMP}}/file.txt"` 或 [env 占位符](./指令与输入配置.md#环境变量-env)。
