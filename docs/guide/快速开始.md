# 快速开始

本文帮助你在 **5～10 分钟内**完成安装、首次运行与基本命令了解。

---

## 前置条件

| 项目     | 要求                                                                      |
| -------- | ------------------------------------------------------------------------- |
| 操作系统 | Windows / Linux / macOS（部分 Action 仅 Windows，如 `ui.*`、`capture.*`） |
| Rust     | 1.85+（edition 2024）                                                     |
| 网络     | 运行 HTTP 类示例时需要                                                    |

---

## 1. 构建

```powershell
git clone <repo-url>
cd corex
cargo build -p corex -p corex-daemon
```

Release 构建：

```powershell
cargo build -p corex -p corex-daemon --release
```

Windows 也可从 GitHub Release 下载 `corex-{tag}-windows-x64.zip`（含 `corex.exe`、`corex-daemon.exe`）。

### 贡献者：本地门禁（可选）

提交前建议安装 pre-commit 与相关 CLI（配置已在仓库根目录）：

```powershell
cargo install cargo-deny typos-cli git-cliff --locked
uv tool install pre-commit
pre-commit install
pre-commit run --all-files
```

- `cargo fmt -- --check`：严格格式门禁
- `cargo deny check` / `typos`：依赖策略与拼写
- `git-cliff -l`：预览 conventional changelog

发版（bump 版本、生成 `CHANGELOG.md`、打 tag）见 [发布与 Changelog](../ops/发布与Changelog.md)。
完整门禁说明见 [架构 — 构建与开发工具链](../reference/架构.md#构建与开发工具链)。

## 2. 运行第一个指令

```powershell
# 方式 A：按名称（在 examples/directives/ 或数据目录中查找）
corex run hello

# 方式 B：指定 YAML 路径
corex run examples/directives/hello.yaml

# 传入输入参数
corex run hello -i who=Corex
```

成功时终端输出 JSON，并在临时目录生成问候文件（默认 `%TEMP%/corex-hello.txt`）。

> 第一次跑时，数据目录里的指令目录还是空的——corex 会先写几条通用指令
> （`system-info` / `dir-tree` / `dir-backup` / `text-fingerprint` / `reminder`），
> 所以 `corex schedule` 一上来就不是空的，可以直接挑一条跑。它们就是普通 YAML，
> 改或删随你，见 [数据目录与状态文件 § 起步指令](../reference/数据目录与状态文件.md#起步指令)。

## 3. 查看可用指令与动作

```powershell
corex schedule
corex actions
```

| 命令                             | 说明                                                                                                            |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `corex run [名称\|路径]`         | 执行指令；省略名称就交互挑选，`-i KEY=VALUE` 传参                                                               |
| `corex run <名称> --remote`      | 交给 `corex-daemon` 执行（插件 Action 只在它那里可用），进度按帧流回                                            |
| `corex run <名称> --dry-run`     | 只解析与校验（含运行时权限门），打印将要执行的步骤                                                              |
| `corex run <名称> --json-events` | 步骤事件按 NDJSON 输出（最后一条是 `result`）                                                                   |
| `corex run <名称> --quiet`       | 不打进度，只留结果                                                                                              |
| `corex run <名称> --timeout 30`  | 只本次运行覆盖单步超时（秒），不落盘                                                                            |
| `corex run <名称> --jobs 4`      | 只本次运行覆盖 `parallel` 最大并发                                                                              |
| `corex history`                  | 列出最近的执行记录；`-n 50` 条数、`--failed` 只看失败、可跟指令名                                               |
| `corex schedule`                 | 列出可用指令名                                                                                                  |
| `corex watch run\|attach\|ps …`  | 文件监听守护：`run` 后台启动、`attach` 看日志（Ctrl+C 不停止）                                                  |
| `corex cron run\|attach\|ps …`   | 定时调度守护（命令与 watch 对称）                                                                               |
| `corex actions [id]`             | 按 bucket 列出 Action ID（`--bucket ui` 只看一组）；给 id 则打印参数表、权限与步骤片段；`--json` 换机器可读目录 |
| `corex validate <path>`          | 校验 YAML；`--strict` 检查权限覆盖，`--watch` 存盘即重校                                                        |
| `corex create [名称]`            | 指令脚手架（交互向导，或 `-t hello\|http\|file\|shell\|cron\|watch`）                                           |
| `corex edit <名称>`              | 用 $COREX_EDITOR / $EDITOR 或系统默认程序打开指令 YAML                                                          |
| `corex schema`                   | 输出指令 YAML 的 JSON Schema（`--write <路径>` 落盘）                                                           |
| `corex completions <shell>`      | 打印 shell 补全注册脚本（候选由 corex 现算，升级后无需重生成）                                                  |
| `corex doctor`                   | 自检数据目录、配置、守护进程、动作与指令                                                                        |
| `corex paths`                    | 打印本次运行用的数据 / 指令目录与 IPC 端点；`--json` 给宿主读（宿主不要自己拼路径）                              |
| `corex repl`                     | 交互式 REPL（首屏列指令与最近运行，Tab 补全）                                                                   |
| `corex daemon run`               | 前台启动 Daemon（IPC 服务）                                                                                     |
| `corex daemon status`            | 查看 Daemon 是否在运行                                                                                          |
| `corex update [--check\|--yes]`  | 自更新：检查 / 安装新版本（见 [自更新](../reference/自更新.md)）                                                |
| `corex ui ...`                   | Windows UI 探测工具（见 [UI 自动化](../topics/UI自动化.md)）                                                    |

全局选项：

- `-v` / `-vv`：提高日志级别（CLI 默认只打进度，不打引擎日志）
- `--dir <路径>`：覆盖指令搜索目录

### Shell 补全

补全脚本是**回调式**的：注册脚本只把 shell 挂回 `corex`，每次按 Tab 都是本进程现算候选，
因此升级 corex 之后不必重新生成脚本。

```powershell
# PowerShell（写进 $PROFILE）
corex completions powershell | Out-String | Invoke-Expression
```

```bash
# bash（写进 ~/.bashrc）
source <(corex completions bash)
```

```zsh
# zsh（写进 ~/.zshrc）
source <(corex completions zsh)
```

`bash` / `elvish` / `fish` / `powershell` / `zsh` 都可以。想临时关掉补全，把 `COMPLETE`
环境变量置空即可（`COMPLETE=` 或 `COMPLETE=0`）。

### Windows 上的中文输出

`corex` 输出 UTF-8，并在启动时把**直连的控制台**代码页设成 UTF-8。如果输出经过
PowerShell 的 cmdlet（`| Out-File`、`| Select-String`）转了手，解码由 PowerShell 决定，
这时中文会乱码——在读方这边设一行即可：

```powershell
[Console]::OutputEncoding = [Text.Encoding]::UTF8
```

`shell.run` / `exec.run` 走的是**管道**，不是控制台代码页：中文 Windows 上 `cmd` 等程序
常按 OEM（CP936/GBK）往管道写。corex 会先按 UTF-8 解，失败再回退 OEM/GBK，并把实时
回显转成 UTF-8 再写到终端——这和「只 `chcp 65001`」不是同一层问题。

想确认当前是什么情况，`corex doctor` 会把「控制台编码」报出来：`65001 (UTF-8)` 是正常，
显示别的代码页（或「未连接控制台」）时 **corex 自己的**中文与符号就可能失真，
`chcp 65001` 可以切过来。

字体或终端跟不上 `✓` / `⠋` 这类符号时，`COREX_ASCII=1` 会把它们换成纯 ASCII：

```powershell
$env:COREX_ASCII = '1'; corex doctor
```

需要机器可读的输出时，`NO_COLOR=1` / `CLICOLOR=0` 关掉颜色（重定向到文件时颜色本来就会
自动关掉）。

## 4. 指令文件放在哪？

解析顺序（`corex run <name>`）：

1. 当前路径下的 `<name>.yaml`
2. **数据目录** `directives/<name>.yaml`
3. 仓库 `examples/directives/<name>.yaml`

| 优先级    | 数据目录                                                                                                  |
| --------- | --------------------------------------------------------------------------------------------------------- |
| 1（优先） | 环境变量 **`COREX_DATA_DIR`**（宿主与测试用它钉住目录）                                                   |
| 2         | `corex.exe` / `corex` **所在目录**（可写时；便携布局）                                                    |
| 3         | Windows `%APPDATA%\corex\data`；Linux `~/.local/share/corex`；macOS `~/Library/Application Support/corex` |
| 4         | 当前目录 `.corex`                                                                                         |

自定义指令可复制到 `<数据目录>/directives/`，或通过 `--dir` 指定目录。

第 2 档意味着 **exe 挪个位置，数据目录就跟着挪**；`.corex` 则是两步都不成立时的兜底。宿主随包分发
corex 时应当用 `COREX_DATA_DIR` 钉住目录，否则「数据落在哪」会取决于 exe 在不在可写位置。
每个文件的用途与生命周期见 [数据目录与状态文件](../reference/数据目录与状态文件.md)。

## 6. 常见问题

### `指令未找到`

- 确认文件名与 `corex run` 参数一致（不含 `.yaml`）
- 或在仓库根目录执行，以便找到 `examples/directives/`

### `permission denied`

指令声明了 `permissions` 但未包含当前 Action 所需类别。见 [指令与输入配置 — 权限](./指令与输入配置.md#权限)。

### HTTP 示例超时

检查网络与 URL；可加大 `timeout_ms` 或使用 `-v` 查看日志。

### watch/cron：send 报错「找不到路径」

操作请使用 **指令名**（`ps` 的 NAME 列），不要用 pid。例如：`corex watch send build-client status`。

### watch/cron：`run` 和 `attach` 有什么区别？

| 命令                                  | 作用                                        |
| ------------------------------------- | ------------------------------------------- |
| `corex watch run <name>`              | **启动**后台文件监听守护（默认 detach）     |
| `corex watch run <name> --foreground` | **前台**启动（开发用，`Ctrl+C` 会停止守护） |
| `corex watch attach <name>`           | **查看**已在运行的守护日志（不启动新实例）  |

`corex cron run` / `attach` 同理。查看日志用 `attach`，不要用 `run`。

### watch attach 退出后任务还在吗？

`corex watch attach` 按 `Ctrl+C` 仅退出查看（detach），**不会**停止后台守护；用 `corex watch stop <name>` 优雅停止，或 `corex watch stop <name> --force` 立即终止进行中的构建。

### Windows 上 `/tmp/...` 路径无效

使用 `-i out="{{env.TEMP}}/file.txt"` 或 [env 占位符](./指令与输入配置.md#环境变量-env)。
