# 指令与输入配置

本文说明如何**编写 Directive YAML**、如何通过 **`-i` 传参**、以及常见输入类型（路径、时间格式、环境变量等）的配置方式。

语法细节见 [directive-yaml.md](../reference/指令YAML.md)；可运行示例见 [examples/directives/README.md](../../examples/directives/README.md) 与 [examples/actions/README.md](../../examples/actions/README.md)。

---

## 1. 最小指令结构

```yaml
name: my-task          # 必填，对应 corex run my-task
description: 说明       # 可选
version: "1.0"         # 可选

inputs:                # 可选：声明外部可传入的参数
  - name: who
    required: false
    default: "world"

steps:                 # 必填：按顺序执行的步骤
  - id: greet
    action: template.render
    params:
      template: "Hello, {{input.who}}!"
    save_to: message
```

---

## 2. 命令行传参（`-i`）

```powershell
corex run hello -i who=Alice
corex run hello --input who=Alice   # 等价
```

| 规则 | 说明 |
|------|------|
| 格式 | `KEY=VALUE`，可多次 `-i` |
| 覆盖 | 命令行传入的值**覆盖** YAML 中 `inputs[].default` |
| 空值 | 传入空字符串或未传且 `default` 为空时，使用 default 解析规则 |
| 路径 | Windows 路径可用 `/` 或 `\`；含空格时用引号：`-i target="C:/path/a b.js"` |

### 在 YAML 中引用输入

| 写法 | 含义 |
|------|------|
| `{{input.who}}` | 名为 `who` 的输入 |
| `{{input}}` | 整个 input 映射 |
| `{{who}}` | 若 `save_to: who` 则优先 variables；否则回退 input |

---

## 3. 默认值（`default`）

```yaml
inputs:
  - name: format
    description: 时间格式
    required: false
    default: "%Y-%m-%d %H:%M:%S"
  - name: out
    default: "{{env.TEMP}}/output.txt"
```

- `default` 支持 **`{{ }}` 占位符**，在合并 input 前会先解析。
- 适合用 `{{env.TEMP}}`、`{{env.USERPROFILE}}` 做跨平台路径。

---

## 4. 环境变量（`env`）

| 写法 | 示例 |
|------|------|
| `{{env.VAR_NAME}}` | `{{env.TEMP}}`、`{{env.HOME}}`、`{{env.USERPROFILE}}` |

常用 Windows 变量：

| 变量 | 用途 |
|------|------|
| `TEMP` / `TMP` | 临时目录 |
| `USERPROFILE` | 用户主目录 |
| `LOCALAPPDATA` | `%LOCALAPPDATA%` 应用数据 |

## 5. 时间格式（`generate.timestamp`）

[`inject-build-time.yaml`](../../examples/directives/inject-build-time.yaml) 等指令通过 `format` 输入控制输出时间字符串。该格式传给 Action **`generate.timestamp`**，底层使用 **Rust chrono** 的 strftime 语法（与 C 风格类似）。

### 示例

```powershell
# 默认：2026-08-27 14:30:00（本地时区）
corex run inject-build-time

# 仅日期
corex run inject-build-time -i format=%Y-%m-%d

# ISO 风格
corex run inject-build-time -i format=%Y/%m/%d_%H-%M-%S

# 写入 package.json
corex run inject-build-time -i json_path=./package.json -i format=%Y-%m-%dT%H:%M:%S
```

### 常用格式符

| 格式符 | 含义 | 示例 |
|--------|------|------|
| `%Y` | 四位年份 | 2026 |
| `%m` | 月份（01–12） | 08 |
| `%d` | 日（01–31） | 27 |
| `%H` | 24 小时（00–23） | 14 |
| `%M` | 分钟（00–59） | 30 |
| `%S` | 秒（00–59） | 05 |
| `%F` | 等价 `%Y-%m-%d` | 2026-08-27 |
| `%T` | 等价 `%H:%M:%S` | 14:30:05 |

### Action 输出字段

`generate.timestamp` 返回：

| 字段 | 说明 |
|------|------|
| `value` | 按 `format` 格式化的字符串 |
| `unix` | Unix 时间戳（秒） |
| `iso8601` | RFC3339 字符串 |

在后续步骤中引用：`{{built_at.value}}`、`{{step.ts.unix}}`（取决于 `save_to` 名称）。

### UTC

```yaml
- id: ts
  action: generate.timestamp
  params:
    format: "%Y-%m-%d %H:%M:%S"
    utc: true
```

## 6. 步骤输出（`save_to` / `step`）

```yaml
- id: fetch
  action: http.send
  params:
    url: "https://httpbin.org/get"
  save_to: response

- id: use
  action: template.render
  params:
    template: "status={{ response.status }}"
```

| 引用方式 | 说明 |
|----------|------|
| `{{response.status}}` | `save_to` 写入 variables 后的简写 |
| `{{step.fetch.status}}` | 显式引用步骤 id |
| `{{variables.response}}` | 完整变量名 |

## 7. 条件与分支（`when` / `if`）

条件可用于 **`when`**（单步是否执行）或 **`if`**（多步分支）。比较前会先解析 `{{ }}` 占位符。

### 条件运算符

| 键 | 含义 | 写法 | 说明 |
|----|------|------|------|
| （字符串） | 真值判断 | `"{{variables.enabled}}"` | 解析结果为 truthy 时为真 |
| `eq` | 等于 | `eq: [a, b]` | 两值相等 |
| `ne` | 不等于 | `ne: [a, b]` | 两值不相等 |
| `gt` | 大于 | `gt: [a, b]` | 数值比较 |
| `lt` | 小于 | `lt: [a, b]` | 数值比较 |
| `and` | 逻辑与 | `and: [条件1, 条件2, …]` | 全部为真 |
| `or` | 逻辑或 | `or: [条件1, 条件2, …]` | 任一为真 |
| `not` | 逻辑非 | `not: 条件` | 取反 |

**步骤级 `when`**（单步是否执行）：

```yaml
- id: patch_json
  action: file.write
  when:
    ne: ["{{input.json_path}}", ""]   # json_path 非空时才执行
  params:
    path: "{{input.json_path}}"
```

**`if` 分支**（多步）：

```yaml
- id: branch
  if:
    eq: ["{{input.mode}}", "prod"]
  then:
    - id: prod_step
      action: template.render
      params: { template: "prod" }
  else:
    - id: dev_step
      action: template.render
      params: { template: "dev" }
```

组合条件示例：

```yaml
when:
  and:
    - ne: ["{{input.json_path}}", ""]
    - eq: ["{{input.mode}}", "prod"]
```

## 8. 权限

```yaml
permissions:
  network: true      # http.send
  filesystem: true   # file.*, copy.run, ...
  shell: true        # shell.run, exec.run
  clipboard: true
  notifications: true
  ui: true           # ui.*
  capture: true      # capture.screenshot, capture.ocr, ...
  secret: true       # keyring.*
```

| 规则 | 行为 |
|------|------|
| **全部省略** | allow-all（简单示例可不写） |
| **任一设为 true** | 仅允许已声明类别；其余 Action → `permission denied` |

企业模式：`config.toml` 中 `[runtime] strict_permissions = true` 会拒绝**未声明任何权限**的指令。

校验：`corex validate path.yaml --strict`
