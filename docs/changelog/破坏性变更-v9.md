# 破坏性变更 — Corex v9

v9 把 daemon 的**服务模型**改对了：连接与执行是两件事，以前被压在同一个串行循环里。

与 v8 相比，这次的破坏面落在**用 `corex-ipc` 自己起服务的 Rust 嵌入方**——用现成的
`corex-daemon` 二进制的人不会撞上编译错误，但会看到一处**行为变更**（见第 2 节）。

---

## 1. `serve_ipc` 的 handler 变成「可克隆 + 可跨任务」

`serve_ipc` 现在**每条连接跑在自己的任务里**，所以 handler 得能被克隆并移进任务：

| v8.1                                                          | v9                                                                     |
| ------------------------------------------------------------- | ---------------------------------------------------------------------- |
| `F: FnMut(Request, Outlet) -> Fut + Send`                     | `F: Fn(Request, Outlet) -> Fut + Clone + Send + 'static`               |
| `Fut: Future<Output = Response> + Send`                       | `Fut: Future<Output = Response> + Send + 'static`                      |
| `PlatformTransport::serve(path, handler)` 的 handler 同理     | 同上                                                                   |

要改的地方通常只有一处：把闭包捕获的东西从「可变借用」改成 `Arc`。daemon 自己就是这么写的：

```rust
let state_serve = Arc::clone(&state);
serve_ipc(&endpoint, move |req, outlet| {
    let state = Arc::clone(&state_serve);
    async move { handle_request(&state, req, outlet).await }
})
```

`Serve` 内部的 `serve_connection` 也从 `&mut F` 改成按值收 `F`（它是 `pub(crate)`，外部看不到）。

---

## 2. daemon：连接并发，执行受 `[daemon] max_jobs` 限制

v8 的 accept 循环是**串行**的：

```rust
loop {
    let conn = listener.accept().await?;
    serve_connection(reader, writer, &mut handler).await?;   // 整个请求跑完才回去 accept
}
```

于是**一条跑着几分钟的指令会让所有别的客户端连不上**——包括 `ping`。而探活正是宿主判断
「daemon 还活着吗」的手段，被堵住是最糟的形态。

v9 把两件事分开：

| 事项       | v9 的行为                                                                       |
| ---------- | ------------------------------------------------------------------------------- |
| 建立连接   | 总是并发（每连接一个任务）。慢请求不再让别的客户端连不上                          |
| 执行请求   | `run_directive` / `invoke` 排队，最多同时 `max_jobs` 个                          |
| 控制请求   | `ping` / `shutdown` / `list_directives` / `list_actions` **不排队**，随时可答     |

新增配置键 **`[daemon] max_jobs`**：

| 值        | 含义                                                                     |
| --------- | ------------------------------------------------------------------------ |
| `1`（默认） | 串行执行。一条指令跑着时别的执行请求在队列里等                            |
| `> 1`     | 最多同时跑这么多                                                          |
| `0`       | 不限                                                                     |

**默认取 `1` 是有意的**：它保持 v8 的**执行**语义（升级后不会有两条指令突然同时驱鼠标键盘——
那必然互相踩），同时把「连不上」那个缺陷修掉。宿主想并发就显式写 `max_jobs = 2`。

对 Rust 嵌入方的附带影响：`DaemonConfig` 从 `#[derive(Default)]` 改成手写 `Default`，
因为 `usize::default()` 是 `0`（不限）而不是想要的 `1`。

---

## 3. 一条连接的 IO 错误不再带走整个 daemon

以前 `serve_connection` 的错误会经 `?` 一路传播到 `serve`，于是**一个客户端粗鲁地断开就能让
daemon 退出**（日志里是一句 `IPC 服务异常`）。现在它只结束那条连接，并以 `debug` 记一行。
只有收到 `bye`（`shutdown` 的回答）才会让服务返回。

---

## 4. 其余（新增与非破坏，但宿主该知道）

这些是同一个版本里落地的，都不破坏线格式，写在这里是因为它们改变了**行为**：

| 变更 | 说明 |
| ---- | ---- |
| **端点发现文件** | daemon 开始服务前写 `<数据目录>/endpoint.json`（`endpoint` / `kind` / `pid` / `token_file`），退出时删。连接方（CLI、宿主、SDK）现在按 **显式配置 → 该文件 → 平台默认** 找端点——不再需要复刻平台目录规则，也不必猜配置里改没改端点 |
| **`COREX_DATA_DIR`** | 新增环境变量，优先级最高，用来钉住数据目录。随宿主分发 corex 时应显式设它，否则「数据落在哪」取决于 exe 在不在可写位置 |
| **`corex actions --json`** | 动作目录的机器可读形态（`params` / `permissions` / `input_schema`）。MCP 工具的 `inputSchema` 可以直接用它 |
| **`list_actions` 回话变大** | 从「一串 id + 名称」变成**完整目录**（80 个动作约 103 KB）。只读 `id` 的老客户端不受影响，但每次请求的流量变大了；只要 id 的场合请自行裁剪（或等 MCP 那条渐进式披露的路） |
| **`corex daemon stop` 真的会停** | 以前只让 daemon 停止干活、进程一直挂着（于是它也留不下清理）；现在进程会退出并删掉端点记录 |
| **`packages/corex-client`** | 新增零依赖 JS 客户端（端点发现 / token / 进度帧分流），`examples/electron/` 是它的宿主示例 |
