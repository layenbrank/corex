# 破坏性变更 — Corex v5

v5 是在 v4 Action 运行时之上的**破坏性**重命名与企业加固版本。  
**没有** v4 IPC/YAML 兼容层。当前 workspace 版本见文末。

## Shortcut → Directive

| 范围 | v4 | v5 |
|------|----|----|
| 领域类型 | `Shortcut` | `Directive` |
| 数据目录 | `<data>/shortcuts` | `<data>/directives` |
| 示例 | `examples/shortcuts/` | `examples/directives/` |
| 文档 | `docs/shortcut-yaml.md` | `docs/reference/指令YAML.md` |
| IPC | `run_shortcut` / `list_shortcuts` | `run_directive` / `list_directives` |
| History JSONL 字段 | `shortcut` | `directive` |
| CLI 文案 | “shortcut” | “directive” / 指令 |

迁移方式：将 YAML 移到新目录；文档 schema（`name`、`steps`、`permissions`）不变。

## UI Action 重命名

| 已移除 | 替代 |
|--------|------|
| `ui.find` | `ui.window.find`（顶层 HWND / 标题） |
| `ui.wait`（窗口等待） | `ui.window.wait` |

新增元素 API（Windows UIAutomation）：

- `ui.element.list` / `ui.element.find` / `ui.element.click` / `ui.element.wait`

顶层窗口用 `ui.window.*`；应用内控件用 `ui.element.*`（`name`、`automation_id`、`control_type`）。

## 企业控制

- `[runtime].strict_permissions` — 拒绝 unrestricted 指令；同时拦截 `corex ui` 探测与需权限 Action 的 daemon Invoke
- `[runtime].filesystem_roots` — 通过 `confine_under` 约束 `file.*` / `copy.*` / `codec.*` 等；并约束 `exec.run` 的 **script** 与 `shell.run`/`exec.run` 的 **cwd**（`shell.run` 的 **command** 不做路径沙箱）
- `corex validate --strict` — 要求声明的权限覆盖全部步骤
- 步骤审计：`<data>/audit.jsonl`（`action_id`、`duration_ms`，已脱敏；无 OCR/HTTP body）
- 预设：[`config/enterprise.toml`](../../config/enterprise.toml)
- 合规：[compliance.md](../ops/合规说明.md)

## 交互式 UI CLI（`corex ui`）

嵌套子命令（已移除的扁平名无别名）：

| 已移除 | 替代 |
|--------|------|
| `corex ui windows` / `ui list` | `corex ui window list` |
| （桌面图标静默列表回退） | `corex ui window desktop` |
| `corex ui find` / `ui at` | `corex ui element get` / `element point` |
| 旧路径下的 pick | `corex ui element pick` |

探测门禁 / 审计 id：`ui.window.list`、`ui.window.desktop`、`ui.element.list`、`ui.element.find`、`ui.element.point`、`ui.element.pick`。  
亦遵循 `[plugins].disabled = ["ui"]`。

## 进程启动（`shell.run` / `exec.run`）

共用同一启动内核；两个 Action 均保留。参数清理：

| 已移除 | 替代 |
|--------|------|
| `shell.run` 参数 `shell: true` | `host: cmd`（Windows）或省略（`auto` → 命令直接 exec） |
| `exec.run` 参数 `capture`（`json` / `text` / `none`） | 始终返回 `{ stdout, stderr, exit_code, success }` |
| `exec.run` JSON/`path` stdout 协议 | 与 `codec.json.parse` / `{{step.*.stdout}}` 组合 |

二者新增可选参数：`host`（`none` \| `cmd` \| `powershell` \| `pwsh` \| `auto`）。

## CLI 与触发器（v5.0+）

| 已移除 / 旧名 | 替代 |
|---------------|------|
| `corex list` | `corex schedule` |
| `http.request` Action | `http.send` |
| `triggers` 类型 `manual` / `hotkey` / `file_watch` | 手动：`corex run`；热键：应用层（Tauri）；监听：`type: watch` + `paths` |

新增 supervisor 命令（引擎 `CronEngine` / `WatchEngine`）：

```text
corex schedule [--dir]
corex watch  run [--foreground|--immediate|--all]|ps|attach|logs|send|stop [--force]|restart
corex cron   run [--foreground|--all]|ps|attach|logs|send|stop [--force]|restart
```

> **CLI 变更：** 原 `watch start` / `cron start` 已合并为 `run`（默认后台）。原 `watch run` / `cron run` 在无 `--foreground` 时等价于 `attach` 的行为已移除；查看日志请用 `attach`。
>
> - `--immediate`：**仅 watch**，supervisor 启动后立刻跑一次 pipeline（YAML `triggers.watch.immediate` 同效）。
> - `stop --force`：发送 `STOP_FORCE`，终止 supervisor 进程树（含进行中的构建）。

YAML `triggers` 仅支持 **`cron`** 与 **`watch`**。见 [directive-yaml.md](../reference/指令YAML.md#triggers)。

## 版本

| 版本 | 说明 |
|------|------|
| **5.1.0**（当前） | supervisor 进程身份 / 强制停止；watch 事件管道；`watch`/`cron` 的 `start` 合并为 `run`；文档分层汉化 |
| **5.0.0** | Shortcut→Directive、企业加固、UI 重命名等（见上文） |

Workspace 包版本为 **5.1.0**。
