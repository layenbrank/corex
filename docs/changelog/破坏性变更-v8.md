# 破坏性变更 — Corex v8

v8 把「名字说了两遍」的地方收干净：动作分组改名 `bucket`、5 个配置键改名、CLI 内部
符号去掉 `cmd_` 前缀。功能上没有任何增强，代价全在**名字**上。

与 v7 相比，这次的破坏面**落在用户手写的配置里**——配置键**不留兼容别名**，且每个
章节都拒绝未知键，所以旧配置不会再被静默忽略，而是当场失败并列出可用键。

---

## 1. `ActionCategory` → `action::Bucket`

`action` 模块已经限定了语义，类型名不必再说一遍「Action」：

| v7.1                                       | v8.0                                |
| ------------------------------------------ | ----------------------------------- |
| `corex_core::ActionCategory`（顶层导出）   | `corex_core::Bucket`                |
| `ActionMeta::category`                     | `ActionMeta::bucket`                |
| `ActionMeta::new(…, ActionCategory::Data)` | `ActionMeta::new(…, Bucket::Data)`  |

新增 `Bucket::ALL` / `Bucket::as_str()` / `Bucket::parse()` 与 `Display`：展示名与小写标识
只有这一份数据表，`corex actions` 因此也不再靠 `format!("{:?}").to_lowercase()` 猜。
插件 ABI 不受影响（`plugin-sdk::PluginActionMeta` 从来不含该字段）。

`corex actions` 的列表改为**按 bucket 分组**，并新增 `--bucket <名称>` 过滤：

```text
$ corex actions --bucket ui
ui（31）
  capture.crop           裁剪图片文件并写出
  …
```

---

## 2. 配置键改名（5 个，**不留兼容别名**）

| v7.1                              | v8.0                | 说明                          |
| --------------------------------- | ------------------- | ----------------------------- |
| `[runtime] ui_max_selector_chain` | `ui_selector_depth` | 名字超过 20 字符；去掉 `max_` |
| `[runtime] ui_max_settle_ms`      | `ui_settle_limit`   | 去掉 `max_` 与单位后缀        |
| `[runtime] step_timeout_secs`     | `step_timeout`      | 单位由文档给出                |
| `[update] timeout_secs`           | `timeout`           | `[update]` 已限定语义         |
| `[update] check_interval_hours`   | `check_interval`    | 同上                          |

同时**每个章节都拒绝未知键**（`deny_unknown_fields`）：旧键不再被静默忽略，而是当场失败并
列出可用键。这比「改名了但没人知道」诚实得多——`strict_permissions` 旁边写错一个字母，
从此不可能悄悄失效：

```text
错误: 配置错误: … 解析失败: TOML parse error at line 2, column 1
2 | check_interval_hours = 12
  | ^^^^^^^^^^^^^^^^^^^^
unknown field `check_interval_hours`, expected one of `enabled`, `check_on_start`,
`check_interval`, `channel`, `repository`, `api_base_url`, `token_env`,
`use_system_proxy`, `require_confirmation`, `timeout`
```

布尔键保持 TOML 惯例（`enabled` / `json` / `strict_permissions` / …），没有套用代码里的
`is_` / `has_` 前缀规则——那是给变量名的规范，不是给用户手写配置的。

---

## 3. `-i` 的失误归到退出码 2

`-i` 少写 `=VALUE`（以及键名为空）以前落进通用失败 1，现在与其它用法失误一致地报 2。
未声明的输入键会在执行前警告一次（`{{input.x}}` 允许动态键，所以只提醒不拦）：

```text
$ corex run hello -i woh=Typo
警告: 未声明的输入 woh（已声明: who、out）
```

---

## 4. CLI 内部：`cmd_*` 前缀消失

模块名已经说明是哪个命令，函数名只表达动作：`run::directive`、`create::run`、
`validate::run`、`scheduler::ps` / `logs` / `stop` / `restart` …。只动 `bins/cli` 内部的
`pub(crate)` 符号，对外无影响。
