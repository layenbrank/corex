# 接入总览

第三方应用可通过三种方式使用 Corex 能力。选择一种主路径即可，必要时组合使用。

---

## 接入方式对比

| 方式             | 进程模型                           | 适用场景                    | 文档                               |
| ---------------- | ---------------------------------- | --------------------------- | ---------------------------------- |
| **CLI 子进程**   | 每次 `corex run` 新进程            | CI/CD、Shell 脚本、任务计划 | [快速开始](../guide/快速开始.md)   |
| **Daemon + IPC** | 长驻 `corex-daemon`，客户端 NDJSON | Tauri、自研桌面壳           | [IPC 接入指南](./IPC接入指南.md)   |
| **JS/TS 客户端** | 同上，但替你做了端点发现与鉴权     | Electron、Node 宿主         | [packages/corex-client](../../packages/corex-client/README.md) |
| **Rust 库嵌入**  | 同进程 `Pipeline`                  | Rust 后端、定制二进制       | [Rust 嵌入指南](./Rust嵌入指南.md) |
| **WASM 插件**    | Daemon 加载 `.wasm` 扩展 Action    | 第三方动作、隔离扩展        | [WASM 插件开发](./WASM插件开发.md) |

```text
                    ┌─────────────────┐
                    │  你的应用        │
                    └────────┬────────┘
           ┌─────────────────┼─────────────────┐
           ▼                 ▼                 ▼
    corex run (CLI)    NDJSON / IPC      corex-engine
           │                 │                 │
           └─────────────────┴─────────────────┘
                             ▼
                    ActionRegistry
                    (builtin + WASM)
```

## 宿主应用与自更新

随宿主一起分发的 `corex.exe` **不应该**在宿主背后自行升级——版本漂移会让宿主与 sidecar 的协议假设失效。

在随包下发的 `corex.toml` 里关掉它：

```toml
[update]
enabled = false
check_on_start = false
```

升级改由宿主的发行流程统一处理（替换 sidecar 后重启 daemon）。若你**希望**让用户自助升级，注意 `corex update` 只替换 `corex.exe`、不动 `corex-daemon.exe`，因此仍建议由宿主决定何时重启 daemon；详见 [自更新](../reference/自更新.md)。

## 推荐路径

### 桌面应用（Electron / Tauri / 自研壳）

1. 构建 `corex-daemon` 为 **sidecar**
2. 应用启动时 spawn daemon（**并设 `COREX_DATA_DIR`**，见 [运行时配置](../guide/运行时配置.md)）
3. 通过 **NDJSON** 发送 `run_directive` / `invoke` / `list_actions`
4. 端点是哪个不用猜：daemon 会写 `<数据目录>/endpoint.json`，见 [IPC 协议 § 端点发现文件](../reference/IPC协议.md#端点发现文件)
5. **Windows 上要想两个宿主能各跑一个 daemon**，除了各自的 `COREX_DATA_DIR`，还得各自给一个
   `socket_path`：默认管道名不随数据目录变，晚起的那个会因管道被占而启动失败（见
   [运行时配置 § `[daemon]`](../guide/运行时配置.md)）

示例代码与说明：

| 宿主     | 位置                                                    | 备注                                                       |
| -------- | ------------------------------------------------------- | ---------------------------------------------------------- |
| Electron | [`examples/electron/`](../../examples/electron/README.md) | 用 [`packages/corex-client`](../../packages/corex-client/README.md)，不必自己拼端点与 token |
| Tauri    | [`examples/tauri/`](../../examples/tauri/README.md)       | 见 [Tauri 接入指南](./Tauri接入指南.md)                     |

### 服务端 / CI

```powershell
corex run hello -i who=CI
corex validate examples/directives/hello.yaml --strict
corex validate examples/actions/shell.run.yaml
```

### Rust 项目内嵌

在 `Cargo.toml` 中依赖 `corex-engine`、`corex-registry`，同进程执行 YAML。见 [Rust 嵌入指南](./Rust嵌入指南.md)。

### 扩展 Action（两种路径）

Corex 里「插件」在架构上分两类，**不要混为一谈**：

| 路径                    | 是什么                                          | 何时用                                       | 文档                                                                   |
| ----------------------- | ----------------------------------------------- | -------------------------------------------- | ---------------------------------------------------------------------- |
| **内置 Action（Rust）** | 编译进 `corex-registry`，与 CLI/daemon 同二进制 | 一方/企业功能、需 native 依赖（UI/OCR/进程） | [Rust 嵌入 — 注册自定义 Action](./Rust嵌入指南.md#3-注册自定义-action) |
| **WASM 插件**           | 数据目录下 `.wasm`，daemon 启动时加载           | 第三方扩展、进程隔离、免重编译宿主           | [WASM 插件开发](./WASM插件开发.md)                                     |

```text
Directive YAML:  action: foo.bar
                        │
          ┌─────────────┴─────────────┐
          ▼                           ▼
   register_builtins()          plugins/*.wasm
   crates/registry/builtin/      WasmPluginHost
   （Rust，生产主路径）           （动态，bindgen 完善中）
```

仓库内新增内置模块：在 `crates/registry/src/builtin/` 实现并注册（可参考现有 `copy`、`http`、`codec` 等；工作区 skill：`corex-add-module`）。

> **生产建议：** 优先 **Directive + 内置 Action** 或 **Rust 嵌入注册**；WASM 在 bindgen 完善前视为实验能力。

## 协议与类型

| 项目         | 说明                                                            |
| ------------ | --------------------------------------------------------------- |
| 请求格式     | NDJSON，每行一个 JSON，`type` 字段区分                          |
| 动态值       | JSON 映射，与 `corex_core::Value` 对应                          |
| 鉴权         | `auth_token` 字段；与 daemon 共享 `COREX_TOKEN` 或 `token` 文件 |
| 协议细节     | [IPC 协议](../reference/IPC协议.md)                      |

## 数据目录与配置

客户端与 Daemon 需约定：

- 同一 **数据目录**（或显式 `--socket` / `socket_path`）
- 同一 **auth token**

配置说明：[运行时配置](../guide/运行时配置.md) · [数据目录与状态文件](../reference/数据目录与状态文件.md)
