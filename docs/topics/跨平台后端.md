# 跨平台后端（Phase 4）

本文跟踪 Windows 以外平台上 capture/OCR 与 UI 自动化的原生后端规划。  
当前 **v5** 以 **Windows 优先** 实现内置能力；其他平台返回明确的执行错误。

## Capture 与 OCR（`capture.rs`）

| Action | Windows（已交付） | macOS（规划） | Linux（规划） |
|--------|-------------------|---------------|---------------|
| `capture.screenshot` | `screenshots` crate（GDI） | `screencapturekit` 或 `core-graphics` | `xcap` 或 `grim`/`scrot` 封装 |
| `capture.monitors` | `screenshots::Screen::all` | `NSScreen` 枚举 | `xrandr` / `wlr-randr` |
| `capture.ocr` | `Windows.Media.Ocr` | Apple **Vision**（`VNRecognizeTextRequest`） | **Tesseract**（`tesseract-rs`） |

### Feature 拆分（提案）

- 保持单一 `act-capture` feature；用 `cfg(windows|target_os = "macos"|target_os = "linux")` 门控 OS 依赖。
- Linux 可选 `act-capture-ocr-tesseract`（原生依赖较大）。
- **不要**单独增加 `ocr.rs` 模块——OCR 统一留在 `capture.rs`。

### macOS 说明

- 从屏幕取图做 OCR 时，Vision 需要屏幕录制相关 entitlement。
- 从文件路径 OCR：`NSImage` → `CGImage` → Vision request；语言用 `recognitionLanguages`。

### Linux 说明

- Wayland 与 X11：截图后端需在运行时或编译期选择。
- Tesseract 语言包属于部署问题（见 [enterprise-deploy.md](../ops/企业部署.md)）。

## UI 自动化（`ui.rs`）

| Action | Windows（已交付） | macOS（规划） | Linux |
|--------|-------------------|---------------|-------|
| `ui.window.*` | Win32 `EnumWindows` | Accessibility `AXUIElement` | **尚未承诺** |
| `ui.window.*` / `ui.element.*` / `ui.click|type|key` | SendInput + UIA | AX API + `CGEvent` | AT-SPI（实验） |

### 权限

- Windows：`PermissionKind::Ui`；OCR/截图另需 `PermissionKind::Capture`。
- macOS：需辅助功能 + 屏幕录制授权（用户在系统设置中授予）。
- Linux：底层输入多限于 X11；Wayland 通常阻止合成输入。

## WASM / 插件

复杂、应用特有流程（企业 IM、自定义选择器）应放在 `plugins/` WASM 宿主。  
内置 Action 保持小块可组合（`shell.run` → `ui.*` 链）。
